Primary memory and the cache

The CPU needs data fast, but big memory is slow. So it keeps a small, very fast cache holding the most recently used items. If the item is there, that is a cache hit (quick). If not, a cache miss: the CPU must wait for RAM, and the item is copied into the cache, pushing out the least recently used item.

RAM – 16 addresses (slow: 100 ns)

Cache – 4 slots, oldest is thrown out first (fast: 1 ns)

Bits, numbers and logic

Binary, decimal and hexadecimal

Computers store numbers as bits (0 or 1). Each bit has a place value: 128, 64, 32, 16, 8, 4, 2, 1. Hexadecimal (base 16) is a shorthand people use because one hex digit stands for exactly four bits.

Method reminders
  • Binary → decimal: add the place values of the 1s.
  • Decimal → binary: subtract the largest place value that fits, repeat; or divide by 2 and read remainders upwards.
  • Binary ↔ hex: split into groups of 4 bits from the right; 0000=0 … 1001=9, 1010=A, 1011=B, 1100=C, 1101=D, 1110=E, 1111=F.
  • Hex → decimal: first digit × 16 + second digit.
  • Decimal → hex: divide by 16: quotient is the first digit, remainder the second.

Sound sampler: analogue in, digital out

Analogue signal (grey wave)The real sound: a smoothly changing amplitude (loudness / air pressure) over time. It has infinitely many values – a computer cannot store that.
Digital signal (copper steps)What is stored: a measurement taken at regular moments, each rounded to the nearest allowed level and written as a binary number.
Sample rateHow many measurements per second (Hz). Time between samples = 1 ÷ rate. Higher rate → the steps follow the wave more closely → more samples → bigger file.
Bit depthBits used for each measurement. n bits → 2ⁿ levels of amplitude. More bits → finer steps (less rounding error) → each sample bigger.

Logic gates

A logic gate is a tiny circuit that takes 1s and 0s in and gives a 1 or 0 out according to a rule. Every part of the CPU – the ALU that adds, the CU that decodes, the registers that remember – is built from millions of them.

Gate tester

Pick a gate, click the inputs, watch the output. Try every input combination for every gate.

All seven rules

Standard symbols: AND is a D-shape; OR has a curved back and pointed nose; NOT is a triangle with a bubble; a bubble on the output turns AND into NAND and OR into NOR; an extra curved line at the back turns OR into XOR (and NOR into XNOR).

4

Truth tables, Boolean algebra and Karnaugh maps

A truth table lists every possible input combination and the output for each. With n inputs there are 2ⁿ rows. Two circuits with the same truth table do the same job, so if you can find a simpler expression with the same table you can build it with fewer gates.

Sum of products (SOP) – from the 1sCircle groups of 1s in sizes 1, 2, 4 or 8 (rectangles, wrap-around allowed, overlapping allowed, as big as possible). Each group becomes a product (AND) of the variables that stay constant inside it – a variable that is 1 appears as A, one that is 0 as A, one that changes is dropped. OR (+) the products together. Example: a group covering A=1,B=0 for both values of C → AB.
Product of sums (POS) – from the 0sCircle groups of 0s the same way. Each group becomes a sum (OR) inside brackets, but with the variables complemented: a variable that is 0 in the group appears as A, one that is 1 as A. AND the brackets together. Example: 0s where A=0,B=1 for both C → (A + B). SOP and POS describe the same function; pick whichever gives fewer gates.

The software that runs the machine

The operating system sits between your apps and the hardware, sharing out the CPU, memory and devices. Control systems use the same idea of sensing, deciding and acting in the physical world. Play with each simulator, then answer. Sections marked HL are Higher Level only.

1

What an operating system is for

Without an OS, every program would have to know how to talk to every printer, disk and screen. The OS abstracts the hardware (you see files and windows, not disk sectors and pixels) and manages resources so many programs and users can share one machine safely.

System integrity

While you work, the OS is busy in the background: indexing files, checking for updates, cleaning temporary files, syncing the clock. It must do this without breaking anything. It keeps integrity by:

  • Protection – each process gets its own memory; a crashing game cannot overwrite your document.
  • Kernel vs user mode – only the OS core may touch hardware directly; apps must ask.
  • Priorities – background jobs run at low priority so the app you are using stays responsive.
  • Safe updates – files are verified (checksums, signatures) and changes can be rolled back if power fails halfway.

Multitasking, contention and deadlock HL

Multitasking means switching the CPU between processes so fast they seem to run together. Every switch costs time (saving and restoring registers). Processes also compete for scarce resources – and if each is holding something the other needs, nobody can move: deadlock.

The OS must also stop processes contending for the same resource from corrupting it – it hands out locks, queues requests, and enforces limits. Deadlock is handled by prevention (e.g. always request resources in the same order), avoidance (refuse a request that could lead to deadlock), or detection and recovery (spot the circular wait and kill or roll back a process).

Translation time vs execution speed

A compiler pays a big cost once, before the program runs, then runs fast. An interpreter starts instantly but pays a little on every line, every time. Which wins depends on how much work the program does. Slide the loop size.

Model used (simplified but realistic proportions)
  • Compiler: 2 000 ms to compile, then 1 µs per loop iteration.
  • Interpreter: no set-up, 30 µs per iteration (each line is decoded again every time).
  • Bytecode + VM: 300 ms to compile to bytecode, then 8 µs per iteration.
  • JIT: as bytecode for the first 10 000 iterations, then 50 ms to compile the hot loop to native code, then 1.5 µs per iteration.
